粘贴 IPA 链接，自动添加应用

无需重新上传 IPA。使用 GitHub Actions 临时下载并解析 IPA，自动识别应用名称、Bundle ID、版本、最低系统版本和部分权限，尽可能找到官方图标。

通过链接添加 IPA ↗
01复制 IPA 的 HTTPS 下载链接支持公开的 GitHub Releases 和其他可直接下载 IPA 的地址
→
02GitHub 点击 Run workflow只需填写 IPA URL，其他字段可留空自动识别
→
03自动识别图标与版本并发布找不到图标时可额外填写 icon_url，之后会自动更新软件源

安全说明：只有对本仓库有写入权限的 GitHub 账号才能执行发布。导入只引用原始 IPA 链接，不复制 IPA；原下载地址失效时，安装也会失效。应用图标若只封装在 Assets.car 内，可能需要手动提供图片 URL。请确认你有权进行相应分发或链接引用。

ONE-CLICK SOURCE IMPORT

把其他 AltStore 软件源导入进来

不需要逐个下载 IPA。将获得授权的软件源 JSON 地址粘贴到 GitHub Actions，即可批量导入应用和历史版本。

开始导入软件源 ↗
01复制对方的软件源地址HTTPS 格式，通常以 source.json 结尾
→
02点击 Run workflow粘贴地址，选择导入全部或指定 Bundle ID
→
03GitHub 自动合并发布导入源数据并重新发布你的 Pages 软件源

支持 JSON/JSON5；默认只添加新应用，可选合并已有应用的历史版本。保留第三方原始 IPA 下载地址，不复制 IPA 文件。需自行确认转载授权，原链接失效时下载也会失效。

ONE-TIME SETUP

首次使用：检查 GitHub Pages

我们已经写入自动发布工作流。只要将仓库的 Pages 发布来源切换到 GitHub Actions，此后发布 IPA 就无需再调整设置。

仓库 Settings → Pages → Build and deployment → Source: GitHub Actions
打开 Pages 设置 ↗
i
关于隐私与权限

管理入口页面本身是公开的，但发布与删除 Release 必须通过 GitHub 自带的账户权限检查。仅靠 GitHub Pages 无法提供真正私有的自定义账号密码页面。自动化可以提取 Info.plist 里的基本信息，但应用签名 Entitlements 不一定能全部自动获取；上传后如有需要，请核对并手动修改 source.json 中的 appPermissions。
